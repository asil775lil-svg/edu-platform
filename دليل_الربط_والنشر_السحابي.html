المرحلة الأولى: تهيئة وربط Firebase (المصادقة السحابية)

تم ربط المنصة بمشروع Firebase الرسمي لتأمين تسجيل الدخول، وحماية الجلسات، وتوفير الدخول بنقرة واحدة عبر Google:

1
إنشاء مشروع Firebase تم الدخول إلى Firebase Console وإنشاء مشروع يحمل المعرّف: smart-education-ed253.
2
تفعيل مزودي تسجيل الدخول (Sign-in Providers) من لوحة Firebase ➔ Authentication ➔ تم تفعيل:
  • Email/Password: لتسجيل المعلمين والطلاب بالبريد وكلمة السر.
  • Google: لتسجيل الدخول الفوري بضغطة زر دون ملء استمارات.
3
استخراج وتصحيح المفاتيح السحابية (firebaseConfig) تم ربط المفاتيح المدققة هندسياً في الواجهة بملف apps/web/src/lib/firebase.ts:

التحقق السحابي في الخادم (FastAPI Backend Verification) تم بناء وحدة app/core/firebase.py لجلب شهادات Google العامة الرقمية تلقائياً من: https://www.googleapis.com/robot/v1/metadata/x509/securetoken@system.gserviceaccount.com والتحقق المشفر من صحة رمز المستخدم (ID Token) وتوليد مفاتيح التوقيع الرقمية المشفرة (Ed25519) له فوراً.

المرحلة الثانية: نشر الواجهة العالمية على Netlify

تم تحويل الواجهة من العمل المحلي localhost إلى شبكة توزيع محتوى سحابية سريعة:

1
بناء نسخة الإنتاج (Production Build) تنفيذ أمر: npm run build داخل مجلد apps/web، والذي يولد الملفات المحسنة في apps/web/dist.
2
النشر بنقرة واحدة (Netlify Drop) سحب مجلد apps/web/dist وإفلاته في Netlify.
3
تخصيص النطاق وإتاحته للعامة تغيير الاسم من الرابط العشوائي إلى الرابط الرسمي: https://edu-platform-ye.netlify.app وجعل صلاحية الوصول Public.
4
إعداد التوجيه السحابي (_redirects) إنشاء ملف apps/web/public/_redirects لربط طلبات الواجهة بالخادم السحابي دون مشاكل CORS: 
/api/*  https://edu-platform-67ju.onrender.com/api/:splat  200
/*      /index.html                                       200

المرحلة الخامسة: خطوات التحديث التلقائي المستمر عبر GitHub

لأن Render و Netlify مرتبطان بمستودع GitHub، يمكنك تحديث المنصة مستقبلاً بأمر واحد فقط من جهازك:

قاعدة ذهبية: بمجرد رفع أي كود إلى GitHub، يقوم Render و Netlify تلقائياً ببناء ونشر التحديث خلال دقيقتين دون أي تدخل يدوي!

أمر التحديث السريع من سطر الأوامر (PowerShell):

# 1. إضافة الملفات المعدلة
git add .

# 2. تسجيل وصف التحديث
git commit -m "تحديث جديد للمنصة"

# 3. إرسال التحديث إلى GitHub (التحديث السحابي التلقائي)
git push origin main

فور تنفيذ git push:

  • يقوم خادم Render بإعادة بناء الخادم وتحديث التعديلات فوراً.
  • يقوم GitHub بحفظ نسخة احتياطية من كل تغيير مع تاريخه.

المرحلة السادسة: هندسة التحديث التلقائي عبر Google Drive

هذه هي الميزة الحصرية التي تمكن المعلم من وضع ملفات المنهج داخل Google Drive لتكتشفها المنصة وتحدّث الدروس تلقائياً:

كيف تعمل دورة المزامنة التلقائية (Workflow)؟

  1. المعلم ينشئ مجلداً على Google Drive (مثلاً باسم المادة: فيزياء_الصف_الثالث).
  2. ربط Google Drive API بالخادم: يتم تزويد خادم FastAPI بمفتاح Service Account أو OAuth 2.0.
  3. الإشعار اللحظي (Webhooks via Google Drive Push): تشترك المنصة في مراقبة المجلد عبر files.watch. فور قيام المعلم بحفظ أو إضافة أي ملف (PDF، فيديو MP4، اختبار Markdown): ترسل جوجل إشعاراً فورياً (Webhook POST) إلى مسار: https://edu-platform-67ju.onrender.com/api/integrations/gdrive-webhook
  4. تحديث المسودة والنشر التلقائي: يقوم الخادم بتحميل الملف وتحديث مسودة الدورة courses.draft وحساب بصمة SHA-256 للملف، ثم نشر Snapshot جديد وتوليد الحزمة الموقعة .edupkg تلقائياً!
  5. تحديث الطالب: واجهة الطالب تتحقق من وجود إصدار جديد عبر الرابط الدائم للملف وتقوم بتحديث المحتوى فوراً.
طريقة المزامنة المكتبية الأسهل (بدون تعقيد):
إذا كان المعلم يملك برنامج Google Drive for Desktop على جهازه، فإن مجلد المادة يكون مجلداً محلياً في جهاز الكمبيوتر (مثلاً: G:\My Drive\المادة). تقوم ميزة "استيراد مجلد" الموجودة في المنصة بقراءة المجلد وتحديث المنهج بضغطة زر واحدة!
