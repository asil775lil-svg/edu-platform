# خطة بناء منظومة المنصة التعليمية الذكية

> **الحالة:** معتمدة — بدأ التنفيذ
> **المالك:** مطوّر واحد (full-time)
> **تاريخ الاعتماد:** 2026-11-15
> **المصدر:** `platform.html` (مستند رؤية أولي)

---

## 1. الفكرة في سطر

منصة يبني فيها المعلم منهجاً كاملاً، يصدّره كملف واحد مستقل قابل للتوقيع والتشفير (`.edupkg`)،
ويستورده الطالب ليدرسه مع تتبّع تقدّمه — أونلاين أولاً، وأوفلاين في v1.0.

**الميزة التنافسية الوحيدة الحقيقية:** `.edupkg` + "استيراد مجلد → منهج".
هذه الميزة لا يقدّمها Google Classroom / Moodle / Notion، وهي قلب المشروع.

---

## 2. تصحيح فرضيات المستند الأصلي

| الفرضية في المستند | القرار الهندسي |
|---|---|
| "DRM يمنع التسريب" | غير ممكن على العميل. الحماية = مفاتيح تُسلَّم أونلاين + علامة مائية (ردع) + علامة جنائية (تتبّع). تُسمّى «حماية المحتوى» بثلاث طبقات. |
| "AI يعمل أوفلاين" | مستبعد. الـ AI أونلاين فقط، مع تدهور رشيق في الواجهة. |
| "دعم كل الصيغ" | DOCX/PPTX تُحوَّل إلى PDF/HTML عند الاستيراد (LibreOffice headless)، لا تُعرض خاماً. |
| "مزامنة تفاضلية + Git للمناهج" | تُبنى كـ **إصدارات ثابتة (immutable versions)** + بصمات محتوى، لا CRDT كامل. |
| "Flutter أو React" | **React/TS فقط** — تصدير HTML المستقل يُشتق من نفس التطبيق لاحقاً. |

## 3. القرارات المعمارية المثبتة

| البند | القرار | السبب |
|---|---|---|
| العميل | React 19 + Vite + TS (SPA) → Tauri لاحقاً | كود واحد للويب وسطح المكتب |
| الخادم | FastAPI + SQLAlchemy 2 + Alembic | async للملفات، OpenAPI يولّد عميل TS |
| قاعدة البيانات | **SQLite في التطوير / Postgres 16 في الإنتاج** | لا Docker على جهاز التطوير |
| التخزين | **نظام ملفات في التطوير / Cloudflare R2 في الإنتاج** | تجريد `Storage` واحد |
| المهام | طابور داخلي في التطوير / Arq + Redis في الإنتاج | نفس الواجهة |
| المحرر | TipTap (ProseMirror) | أفضل دعم RTL ومحرّر كتل جاهز |
| التشفير | Ed25519 + AES-256-GCM + Argon2id عبر `pynacl`/`argon2-cffi` | لا اختراع تشفير |
| الحزم | Python للبناء + TS للتحقق السريع في المتصفح | منع رفع مكرر قبل الشبكة |
| MVP | Studio + Library + `.edupkg` — أونلاين فقط | 9–11 أسبوعاً |

### التعديلات بسبب «مطوّر واحد»

1. **لا جداول `units`/`lessons` في MVP.** الشجرة كلها `JSONB`:
   `courses.draft` للتحرير، `course_versions.snapshot` نسخة ثابتة عند النشر،
   و`lesson_index` مسطّحة تُبنى عند النشر للبحث. يوفّر ~3 أسابيع.
2. **لا ترانسكودينج ولا HLS.** MP4 كما هو + `<video>` + Range requests.
3. **لا `edupatch` ولا «مقيد بحساب».** الطبقات: `open` / `read-only` / `invite-code`
   (AES-GCM بمفتاح مشتق بـ Argon2id من الرمز).
4. **لا تصدير HTML مستقل في MVP.** مؤجّل إلى v1.0.
5. **اشترِ لا تبنِ:** `fastapi-users`-style auth، TipTap، `pynacl`، Resend.

## 5. نموذج البيانات (MVP)

```sql
users            (id, email, password_hash, name, role, created_at)
courses          (id, owner_id, title, description, draft_json, published_version_id)
course_versions  (id, course_id, seq, snapshot_json, checksums, created_at)
lesson_index     (version_id, lesson_id, unit_id, title, order)   -- مشتقة عند النشر
assets           (id, owner_id, sha256, mime, size, storage_key, status)

progress         (id, user_id, course_id, lesson_id, status, position, updated_at)
```

لا يُعاد توليده أبداً، وإلا انكسر تقدّم الطلاب عند كل نشر.

## 8. نقاط تقنية حاسمة

- **بصمة قبل الرفع:** الواجهة تحسب SHA-256 في Web Worker وترسل القائمة؛ السيرفر يرد بالموجود فقط.
- **Canonical JSON** قبل التجزئة والتوقيع + golden vectors مشتركة بين Python وTS.
- **حدود فك الضغط:** نسبة ≤ 100:1، ≤ 500 ملف، ≤ 2GB، رفض `..` والمسارات المطلقة، تجريد `<script>`.
- **بحث عربي:** تطبيع (تشكيل، أ/إ/آ→ا، ى→ي، ة→ه) + `pg_trgm`/`LIKE` مطبَّع.
- **أمان:** Argon2id، جلسات HttpOnly + CSRF، فحص magic bytes، Signed URLs 15 دقيقة، CSP.

### بوابة الأسبوع 4: RTL والاختبار الآلي

**صقل RTL** (عربي + كود + روابط في نفس الفقرة):

| الحالة | قبل | بعد |
|---|---|---|
| فقرة إنجليزية داخل درس عربي | تُحاذى يميناً وتتقدّم علامات الترقيم | `dir="auto"` لكل فقرة → اتجاهها من أول حرف قوي |
| كود داخل جملة عربية (`console.log('x')`) | تنقلب الأقواس والرموز | `direction: ltr` + `unicode-bidi: isolate` |
| كتلة كود كاملة | بلا نمط موحّد | `pre` بخلفية وحدود وتمرير أفقي وLTR |
| رابط داخل نص | بلون النص بلا تمييز | لون + تسطير + عزل اتجاهي |
| بريد/رمز دعوة/بصمة/اسم ملف | تُكتب باتجاه عربي | حقل `input-ltr` + `bidi-ltr` |
| سهم «رجوع» | `←` (اتجاه خاطئ في RTL) | `→` |
| أدوات الكتلة والمسافات | `left` / `padding-left` ثابتة | خصائص منطقية (`inset-inline-end`, `inline-start`) |
| تباعد حروف العنوان | `letter-spacing` يكسر وصل العربية | `normal` |

**اختبار Playwright** (`apps/web/e2e/full-flow.spec.ts`): يشغّل خادماً معزولاً
(API على 8021 بقاعدة `data/e2e.db` وتخزين `storage-e2e`، والواجهة على 5174) ثم:

تسجيل معلّم ← إنشاء مادة ← وحدة ودرس ← عنوان + نص عربي فيه كود داخلي + سؤال +
صورة مرفوعة + فقرة إنجليزية ← التحقق من الحفظ التلقائي عبر الـAPI ← نشر إصدار 1 ←
تصدير حزمة موقّعة وتنزيلها والتحقق من ترويسة ZIP ← تسجيل طالب ← استيراد الحزمة ←
دراسة الدرس ← إجابة السؤال ← إكمال الدرس ← ملاحظة تبقى بعد إعادة التحميل.
كما يتحقق من `lang="ar"` و`dir="rtl"` و`:dir(rtl)`/`:dir(ltr)` لكل فقرة و
`direction: ltr` للكود.
